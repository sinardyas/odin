Lesson 1 · Foundation

The private network itself: VPC & subnets

Before load balancers, before VPNs — the empty plot of land everything else gets built on.

Where this sits → You can launch an EC2 instance, but the network it lands in is a black box. This lesson opens the outermost layer of the blueprint: the VPC and the subnets inside it. Every later box lives inside these.

1. A VPC is a private plot of land with an address range

A VPC (Virtual Private Cloud) is your own isolated network inside AWS. Nothing can enter or leave it except through doors you add. You define it with one thing up front: a range of private IP addresses, written in CIDR notation.[aws]

10.0.0.0/16     ← the whole VPC
└─ the "/16" means: the first 16 bits are fixed (10.0.*.*)
   → 65,536 addresses to hand out, from 10.0.0.0 to 10.0.255.255

Read the slash as "how much is locked down." A smaller number = a bigger range: /16 is huge (65k), /24 is modest (256), /28 is tiny (16). That's the whole trick to reading these.[aws]

2. Subnets carve the plot into usable lots

You don't put servers directly in the VPC. You slice its address range into subnets — smaller ranges, each living in exactly one Availability Zone (a physically separate datacenter).[aws]

Why two of everything? If Availability Zone A's datacenter loses power, a design that lives only in AZ A goes dark with it. Duplicating your subnets across AZ A and AZ B means one datacenter can fail and your app stays up. This is the reflex behind almost every production AWS diagram.[aws]

A small "gotcha" for later A /24 has 256 addresses but AWS reserves 5 in every subnet, so you actually get 251 usable ones. Worth knowing when a subnet mysteriously "fills up."[aws]

3. "Public" and "private" are roles, not walls

Notice the diagram labels some subnets public and some private. Here's the part that surprises most people: those labels aren't a setting you toggle. A subnet is "public" only because of a rule in its route table that sends internet traffic to a gateway — and "private" simply means that rule is absent.[aws]

Don't memorise this wrong There is no "make this public" checkbox that matters. The route table decides. We open that box in Lesson 2 — for now, just hold the idea that public vs private is about routing, not naming.

Check yourself

Answer from memory — the struggle is what makes it stick.

Q1. Which CIDR block hands out the most IP addresses?
Correct. A smaller slash number fixes fewer bits, leaving more addresses free: /16 = 65,536, /24 = 256, /28 = 16.
Not quite — a smaller number after the slash means a bigger range. /16 (65,536) beats /24 (256) and /28 (16).
Q2. Why does the design place a copy of each subnet in a second Availability Zone?
Correct. AZs are physically separate datacenters; spreading across two means a single-location failure doesn't take you offline.
The reason is resilience: AZs are separate datacenters, so spreading across two lets one fail without downtime. (A subnet actually lives in exactly one AZ.)
Q3. What actually makes a subnet count as "public"?
Correct — it's the route table, not a name or a toggle. This is the single idea that unlocks Lesson 2.
It's the route table: a public subnet has a route sending internet-bound traffic to a gateway. No magic checkbox, and size is irrelevant.
